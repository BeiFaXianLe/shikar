# 协作流程与角色（2026-11-09 更新）

> 本文件说明 shikar 项目各类工作由谁负责。**产品设计与代码审核使用 Codex。**

## 角色分工
| 工作 | 负责方 | 说明 |
|---|---|---|
| **产品设计**（PRD / 信息架构 / 交互 / 原型） | **Codex** | 由协调会话调用 Codex CLI（只读评审）产出方案，整理进 `docs/` |
| **代码审核（Code Review）** | **Codex（在独立 review 会话中执行）** | 每条 PR 开一个独立的「代码审核」会话（与开发会话并列、可在 session 列表看到），在该会话中调用 Codex 审核，结论写入 `docs/`，问题回传开发会话修复 |
| 功能实现 | SuperAgent 开发者（`workbuddy/deepseek-v4-pro`） | 在独立 worktree 实现、开 PR |
| 架构评审 | 架构师（`workbuddy/glm-5.3`） | 技术方案 |
| 测试 | 测试员（`workbuddy/minimax-m3.1-flash`） | 用例与回归 |
| 产品验收 | （`agentrouter/gpt-6.1-sol`） | 必须基于真实运行结果 |
| 协调 | 协调会话（`workbuddy/deepseek-v4.1-flash`） | 拆分/派单/汇总/合并 |

## Codex 使用方式（本机）
- CLI：`C:\Users\Admin\AppData\Local\OpenAI\Codex\bin\<hash>\codex.exe`
- 产品设计评审：`codex exec -s read-only -C <repo> "<需求/评审提示词>"`
- 代码审核：`codex review` 或 `codex exec -s read-only "评审这次改动 …"`
- 原则：**只读优先、不让 Codex 直接改文件**；评审结论由协调会话转成修复项；Codex 不代替人签字/合并。
