## 1. 问题与复现

**现象**：冷缓存 + 多并发时 `/api/commute` 返回 500 `database is locked`。
testWorker 口径（6 个全新坐标对 ×10 轮）为 37–47 次 500；本机用「单批 2.5s 的可控延迟假上游 + 200 候选（3 批）」复现，6 并发中 4 个 500：

```
elapsed 12.7s
codes: [200, 200, 500, 500, 500, 500]
  0 (500, '{"error": "内部错误: database is locked"}')
```

**根因**：`commute_for` 的 `save()` 用 `conn.execute(INSERT …)` 打开写事务后不提交，driving 分支的 `_table_multi_source`（OSRM 网络调用）在事务内逐批执行，直到循环末尾才 `conn.commit()`。**写事务横跨数秒网络调用**；并发请求各自持有独立连接，互相等 SQLite 写锁，`busy_timeout=5000` 耗尽 → `OperationalError` 未分类 → 500。

`e66303d` 解决的是「同一连接交叉」，不解决「写事务持锁跨网络」，两者独立。

## 2. 变更目的

1. **写事务绝不跨网络调用**：所有上游计算完成后再开事务、批量写入、立即提交。
2. 并发冷缓存下不出现 `database is locked`；真出现时给出明确错误而不是 500。
3. 用例必须能在真实持锁窗口下抓住这个缺陷（现有用例 mock 网络、事务瞬时完成，覆盖不到）。

## 4. 每文件修改点

### 4.1 `commute.py` — 写入路径重构

1. 删除 `commute_for` 内 `save()` 的「执行 + 立即计入 cached」逻辑，改为：

   ```python
   pending: list[tuple[str, float, float]] = []   # (community_id, t_a, t_b)

   def buffer(cid, ta, tb) -> None:
       pending.append((cid, ta, tb))
       stats["computed"] += 1
   ```

2. 新增模块级 `_flush_cache(conn, key, rows) -> dict`：
   - 单事务内 `executemany` 或逐条 `INSERT … ON CONFLICT`，随后一次 `commit()`；
   - 事务时长只与写入行数相关（200 行量级，毫秒级），**函数内不发起任何网络调用**；
   - 捕获 `sqlite3.OperationalError`（含 `database is locked`）→ `rollback()` 后抛 `CommuteError("busy", "缓存写入繁忙，请重试", partial=…)`；
   - 返回写入后的 `{community_id: (t_a, t_b)}`，供上层作为 `cached` 使用。

3. driving 分支：
   - 网络循环内只用 `buffer()`，不再 `conn.execute`；
   - 每批 `_table_multi_source` 返回后仅累积；循环结束（或预算截断）后调用一次 `_flush_cache`；
   - **异常路径**：网络阶段抛 `CommuteError` 时，先把已缓冲行 `_flush_cache` 落库并提交，再把结果挂到 `exc._cached` 后抛出——已算出的结果不再丢失（顺带消除 P2-3 的「未提交悬挂事务」）。

4. transit 分支同样改为 `buffer()` + 循环后一次 `_flush_cache`；`stats["attempted"]/["failed"]/["partial"]` 语义不变，全失败 502 的逻辑（`e6e0bec`）保持不变。

5. 事务边界与回滚语义（明确写死，避免再次漂移）：
   - 一个请求最多一个写事务；
   - 事务内只有 INSERT，没有 HTTP；
   - 任一步失败 `rollback`，缓存不出现半写状态；
   - 进程崩溃时该请求的缓存整体丢失——可接受（缓存，不是账本）。

### 4.2 `api.py`

- `_COMMUTE_ERROR_STATUS` 增加 `"busy": 503`。错误分支已按 `kind` 映射，无需其它改动；`partial` 字段沿用 `e6e0bec`。

## 8. 风险与退路

| 风险 | 退路 |
|---|---|
| 单事务写入 200 行时仍与他请求的写冲突 | 写入前 `BEGIN IMMEDIATE` 先取写锁（寿命仍是毫秒级）；必要时加一次重试 |
| 失败路径先 flush 再抛错，掩盖原始错误 | flush 失败只记入日志级信息，原异常照抛；flush 成功才挂 `_cached` |
| 内存缓冲在超大候选下增长 | 候选上限由 `_COMMUTE_MAX_*` 保证（≤200） |
