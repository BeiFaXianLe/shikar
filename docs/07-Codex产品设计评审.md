# Codex 产品设计评审（shikar 功能扩展）

> 来源：本机 Codex CLI（`codex exec -s read-only`，只读、不改文件）对 `docs/05`、`docs/06`、`prototype/index.html`、现有前端所做的评审。
> 结论一句话：**把功能组织成「先筛小区 → 再查周边 → 最后算通勤」的决策流程；P1 先做地铁筛选 + 筛选页重构。**

---

## 1. 信息架构与导航
一级导航建议：**首页｜找小区｜学校｜医院｜通勤**
- **「找小区」承接现有「小区目录」**（目录作为副标题即可，不要两个相近页面）。
- **地铁不单独占一级导航**，它是「找小区」的主筛选。
- **高铁放在「更多条件 → 高铁出行」**，后续可复用「地点详情 + 周边小区」组件。
- 城市上下文在不同页面间共享；切换城市时清理失效的下级条件并提示。
- 从详情返回要**保留筛选/排序/页码/滚动位置**。
- P1 先只显示「首页、找小区」，其余入口随真实数据开放；首页数据不足时也要给「找小区」入口。

| 入口 | 核心任务 |
|---|---|
| 首页 | 行情概览 + 数据覆盖/期次 + 找小区入口 |
| 找小区 | 综合筛选（城市/价格/地铁/更多条件）→ 详情 / 转通勤 |
| 学校 | 先选学校（/校区）→ 周边最近小区 → 带入找小区 |
| 医院 | 先选医院（/院区）→ 周边最近小区 → 带入找小区 |
| 通勤 | 候选范围 + 地点 A/B + 方式 + 权重 → 加权时间排序 |

---

## 2. 筛选页重构（重点）
### 2.1 布局（三主筛选 + 结果紧接）
- 页面标题：「找小区」+ 一句说明。
- **主筛选行：城市 ｜ 地铁线路 ｜ 参考单价区间 ｜ 更多条件**（控件高度统一 40–44px）。
- **已选条件行**：自然语言 chips + 「清除筛选」。
- **结果工具条**：结果数、覆盖提示；小区名搜索、排序。
- **结果列表**：主体，底部分页。
- 目标：1366×768 下，主筛选+chips ≈140px 内，首屏≥5 条结果（需实测）。
- 小区名搜索放结果工具条，不算第四个主筛选；区/板块进「更多条件」。

### 2.2 「更多条件」抽屉（分组，逐步启用）
右侧 ~440px 抽屉（移动端全屏）。每组最多并排 2 个控件；**距离用「常用值按钮 + 数值输入」（500m / 1km / 2km / 自定义），少用滑杆**。
| 分组 | 控件 | 默认/规则 |
|---|---|---|
| 区域与价格口径 | 区、板块、价格期次 | 默认不限（价格默认当期） |
| 地铁细化 | 指定站点、距离、筛选方式 | 选线路后默认「距站≤1km」；站点默认「线路内任意站」 |
| 周边学校 | 阶段、指定学校、最大距离 | 默认**不启用**；启用后 2km |
| 医疗 | 等级、指定院区、最大距离 | 默认不启用；启用后 3km |
| 高铁出行 | 最大距离（后续加指定车站） | 默认不启用；启用后 5km |
| 通勤比较 | 候选范围摘要 + 进入通勤页 | A/B、权重统一在「通勤」页配置 |

- 地铁两种口径分开命名：**站点附近**（到站直线距离）/ **线路附近**（到线路走向距离，次级项，提示“近线路≠近进站口”）。

### 2.3 字段取舍（删/留/改）
- **保留强化**：地铁线路（先选城市、可多选）、城市（补入主筛选）、价格（改叫「参考单价」元/㎡）、区/板块/搜索、学校阶段（改叫「学校阶段」）、学校/医院/高铁的距离（整组默认关闭）。
- **删除**：找小区页的「地点 A/B、通勤方式、权重」（移到通勤页）、常驻通勤公式说明、**「对口小学」→ 改「附近小学」**（无官方对口数据前不写“对口”）。
- **移动**：学校「辐射小区数/平均距离」、医院「最近距离」移到详情，不做列表主列。
- 不建议本期加：总价预算、重点校评分、综合宜居分（缺面积/名单/解释成本）。

### 2.4 默认值与 chips 规则
- **默认值必须代表“没有限制”**：地铁/价格/学校/医疗/高铁默认不限或未启用；2km/3km/5km 只在启用后生效（**现原型“医院等级=不限、但距离仍过滤”是 bug，P1 一起修**）。
- chips 自然语言：`北京｜4号线·距站≤1km｜小学≤2km｜三甲医院≤3km`；删一个 chip 连带解除该组。
- 主筛选即时生效；抽屉是草稿，点「应用条件」才生效；改条件回第 1 页；“清除筛选”保留城市。

### 2.5 视觉/移动端
- 保留纸面年鉴（宋体标题/米白/细线/朱砂靛蓝），**减少装饰边框**，分组靠标题+间距+细线；chips 浅底+清晰删除。
- 移动端只留「筛选·条件数」「排序」入口；摘要最多两行；筛选面板底部固定「取消/应用条件」。

## 3. 结果层级与排序
- **主行**：小区名 + 参考单价（当前排序指标如距离/通勤同步突出）。
- **次行**：城市·区·板块；价格期次与来源；**当前已启用条件对应的匹配摘要**（解释“为什么符合”）。
- **展开区**：其他学校/医院/高铁信息、完整距离口径、数据覆盖。
- **价格必须带期次**：2019 参考价不能用“最新价格”的视觉，也不能和 2026 价无提示地争“最便宜”。
- 默认排序按任务：目录=稳定顺序；地铁=最近匹配站/线距离升序；学校医院=到选定地点距离升序（Top20=最近，不代表质量）；通勤=加权时间升序；用户选价格=同期次价格排序、缺失价置后。
- 规则：缺失距离≠0；无坐标不进空间筛选但要提示；“三甲≤3km”必须找范围内满足等级的医院；选4号线要取“最近匹配站点”而非全局最近站。

## 4. 三功能流程与边界态（要点）
- **地铁**：选城市→选线路→默认距站≤1km→结果；多线路“任一”；换乘站保留身份；距离判定用未四舍五入值。
- **学校/医院**：左列表右详情（移动端独立详情页），解决“详情出现在长表格底部”问题；详情含名称/校区或院区/地址/阶段或等级/来源时间 + 周边最近小区（含价与期次）；**学校页常驻“周边距离不代表对口或入学资格”**。
- **通勤**：筛候选→确认范围→**选择具体地点（不是自由文本）**→选方式→**按钮触发计算**→看 A/B 时间→调权重（**只重排，不重新请求**）；加权值叫「加权时间」分钟；50/50 叫「**等权**」（说明平均最优可能牺牲一人）；候选截断必须显式选择并标注范围。
- 关键边界态文案：空结果/加载/失败/缺坐标/缺 POI/ Top20 不足 20 / 对口未核验 / 通勤地点重名 / 计算中 / 部分路线不可用 / 额度不足 / 缓存较旧 / 历史价仅 2019 / 趋势数据不足——**都要说明原因并给下一步**。

## 5. 分期
| 阶段 | 重点 |
|---|---|
| **P1 地铁 + 筛选页重构** | 统一目录入口；三主筛选；更多条件框架；chips；城市→线路→站点；站点/线路口径；结果分层与排序；移动端筛选 |
| P2a 学校与医院 | POI、校区/院区身份、目录、详情+最近小区、组合筛选 |
| P2b 高铁与数据补全 | 高铁距离筛选、核验车站类型、补坐标与来源 |
| P3 双点通勤 | 候选管理、地点确认、显式计算、缓存与额度、权重重排、部分失败处理 |

P1 即可形成完整可用版：**地铁附近找小区 + 看价格 + 进详情**。

## 6. 风险（必须约束）
1. **“对口/学区”误导**：当前只能叫「附近学校」；对口需官方年度依据+校区+适用条件。
2. **2019 与 2026 价格混用**：每条带期次；筛选/排序默认同期；历史价分组。
3. **只取全局最近 POI**：必须“先按条件匹配、再取最近”，否则漏掉“稍远但满足等级”的医院。
4. **预计算半径 < UI 上限**：控件上限由实际覆盖决定。
5. **通勤候选截断不透明**：必须显式选择并标明“仅在这 N 个中比较”。
6. **“零依赖”≠“零费用/全离线”**：区分运行库依赖 / 数据获取 / 在线路线服务。
- 另：**817 个小区缺坐标、且大量价格仍是 2019 快照**——页面需分别说明「空间覆盖」与「价格时效」。

## 7. 待确认
- 地铁默认口径：站点附近（主）/线路附近（次）。
- “当期”价格定义：指最近导入批次，而非各小区各自最新一条。
- POI 来源/许可/覆盖半径。
- 学校对口与重点名单。
- 通勤默认策略：加权平均；50/50 命名“等权”；双方上限可选。
- 候选上限/额度/缓存有效期（200 只是示例；N 候选≈最多 2N 组起终点，不等于请求数/账单）。
