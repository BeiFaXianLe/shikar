# shikar（狩鹿）· 调研报告

> 项目：仿《趋势动物》的**网页版**二手房趋势看板
> 范围：**北京、天津** 两城，**小区级**颗粒度
> 版本：v0.1（2026-11-06）｜阶段：Phase 1 · 调研

---

## 1. 竞品 / 对标分析

### 1.1 对标产品：趋势动物（小程序 Pro）
| 维度 | 情况 |
|---|---|
| 形态 | 微信公众号「趋势动物」+ 小程序「趋势动物Pro」+ 知识星球（940+ 成员，运营 4 年+） |
| 主理人 | 聂聪（nick）：6 年房产投资 + 3 年量化交易，现全职独立开发 |
| 核心能力 | 把**房产 / A股 / 大宗商品**行情合成一个可读的「**温度**」/趋势信号，降低普通人看行情门槛 |
| 关键功能 | ① 全国/城市/区级房价趋势与温度；② 可看某区房价、平米单价；③ A股、大宗商品温度；④「推演」功能（2026-10 上线，情景推演） |
| 方法论 | 趋势交易：右侧确认、机会成本、趋势分「立夏→立秋」多阶段、用乖离率判极值 |
| 商业模式 | 知识星球会员 + 小程序（推测免费+增值） |

**结论**：趋势动物的护城河是「**把多指标压成一个温度值 + 趋势阶段 + 可解释信号**」的产品化体验，而不是底层数据（数据多为公开可获取）。

### 1.2 同类/邻近竞品
| 产品 | 定位 | 差异点 |
|---|---|---|
| 中指云 / 中指研究院 | 房地产专业数据与研究 | 面向机构，重报告、重付费，个人体验弱 |
| 贝壳研究院 / 贝壳找房 | 交易平台自带行情 | 数据自有（闭环），但只服务自身平台、无跨小区「温度」抽象 |
| 冰山指数 | 城市级房价指数 | 城市/板块级，偏指数，不到小区颗粒 |
| 各类「房价温度计」网页 | 零散小工具 | 指标单一，无趋势阶段、无推演、无小区下钻 |

**shikar 的差异化切入点**：
1. **只做北京 + 天津**，做深小区级（竞品多数只到城市/板块）；
2. **温度 + 阶段 + 右侧信号** 三层表达（不只给一个数字）；
3. **网页端**（无需装小程序），可做较重的图表与多小区对比。

## 2. 目标用户与场景

| 用户 | 核心痛点 | 用 shikar 做什么 |
|---|---|---|
| 刚需/改善购房者 | 只看「均价涨跌」太粗，不知道**自己关注的小区**现在该不该出手 | 查目标小区温度/阶段，判断「冰点/回暖/过热」 |
| 卖房业主 | 不知道挂牌价定高还是定低、市场在升温还是降温 | 看小区去化率、议价空间、同板块对比 |
| 房产经纪人 | 需要给客户一个「说得清」的市场依据 | 用温度曲线/对比图做沟通素材 |
| 投资客 | 想找「刚启动（右侧确认）」的小区 | 排行榜：升温最快/降温最快 + 信号历史 |

**核心场景（Top 3）**
1. 「我在看朝阳区某小区，现在买合适吗？」→ 小区详情页看温度 62（升温）+ 右侧买入信号成立 → 辅助决策。
2. 「同价位三个小区选哪个？」→ 多小区对比页横向比温度/去化/议价。
3. 「我关注的 5 个小区有异动提醒吗？」→ 自选 + 异动（温度突破阈值/信号翻转）通知。

## 3. 数据源调研（北京 / 天津 小区级）

> 小区级是本产品最难的一环：**数据的可获取性 + 合规性** 决定成败，技术本身不难。

| 数据 | 候选来源 | 粒度 | 成本 | 合规风险 |
|---|---|---|---|---|
| 小区挂牌/参考均价 | 链家小区页（bj.lianjia.com/xiaoqu、tj.lianjia.com/xiaoqu），页面含「参考均价、比上月、在售套数、历史成交套数、关注人数、周报挂牌均价」 | 小区 | 免费(采集) / 授权付费 | **高**（爬取有判例风险） |
| 小区历史成交 | 链家「查成交」/ 贝壳成交记录 | 小区/套 | 同上 | **高** |
| 在售 / 挂牌量 | 链家/贝壳/安居客/我爱我家 | 小区 | 采集 | 高 |
| 带看量 | 贝壳（部分城市） | 小区 | 采集 | 高 |
| 官方成交网签 | 北京住建委、天津住建委公开数据 | 城市/区 | 免费 | 低 |
| 城市房价指数 | 国家统计局 70 城 | 城市 | 免费/公开 API | 低 |
| 已公开数据集 | 链家历史数据集（Kaggle/和鲸等社区整理） | 小区/房源 | 免费/低价 | 中（来源授权不明） |

**关键法律事实**（务必读）：
- 已有判例：被告抓取并存储贝壳网房源信息、交易信息、户型图等，被认定构成**不正当竞争**（见 [iCourt 案例分析](https://www.icourt.cc/prac-document/139770.html)、[北京海淀法院法官观点](https://bjhdfy.bjcourt.gov.cn/article/detail/2024/01/id/7755936.shtml)、北京知识产权法院涉数据反不正当竞争典型案例）。
- 结论：**直接大规模抓取贝壳/链家房源明细与图片向外提供，法律风险很高**。规避方式见《02-代价与可行性分析》§3。

**数据可行性结论**：
- 「小区均价 / 在售套数 / 历史成交套数 / 关注数」这类**聚合指标**在链家小区页**公开可见**；
- 若只做**低频聚合指标 + 回链来源 + 不存储房源明细/图片**，风险显著低于抓「房源库」；
- **强烈建议**：MVP 阶段优先用「授权数据 / 公开数据集 / 官方数据」打底，采集层做成**可插拔 adapter**，随时可换成合规源。

**本项目选型（已确认）**：**个人自用、零付费、本地部署**，数据固定 **B 档（小区级聚合指标）**——不含逐套成交、不含房源明细/图片、不含任何个人信息。该组合法律风险低、成本≈0，详见《02-代价与可行性分析》§8。

## 4. 指标口径调研（「温度」怎么算才不玄学）

参考趋势交易方法论，把小区行情拆成 4 个可观测维度：

1. **价格动量**：挂牌均价环比（4 周 / 13 周）、同比；
2. **成交活跃 / 去化**：近 30 天成交量 ÷ 在售套数（去化率代理）；
3. **议价空间**：1 − 成交均价 ÷ 挂牌均价（越大越冷）；
4. **需求热度**：关注人数增速、带看量（如有）。

> 原则：**每个指标先做城市内百分位归一化（0–100）**，再加权成「温度」；阶段用「温度水位 + 动量方向」二维判定，保证**可解释、可回测**，避免黑箱。

## 5. 调研结论

1. **产品方向成立**：趋势动物的「温度化」表达被市场验证（940+ 付费星球成员）；
2. **网页版可行且有差异化**：只做京津小区级 + 三层表达（温度/阶段/信号）+ 对比/推演；
3. **最大风险不是技术，是数据合规**：必须从第一天就把「数据来源合规」作为架构约束；
4. **建议先做轻量 MVP**：小区级聚合指标 + 温度/阶段 + 小区详情/对比，验证「温度」是否真的好用，再扩数据与推演。
