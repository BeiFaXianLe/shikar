> 来源：GitHub issue #45 / #46；产品方 2026-11-23 补充要求「要支持模糊查询」。
> 原型（验收基准，宝拉已确认方向）：`prototype/f01-home-search.html`、`prototype/f02-back-nav.html`
> 实现方：开发智能体。产品研发只出原型与验收口径，不写业务代码。

## 目标

1. **F-01**：首页第一屏就能按小区名称 / 地址搜索，回车或点搜索直达结果页。
2. **F-02**：详情页「返回」按真实来路回退（A → B 后返回到 A），无来路兜底回目录。
3. **模糊查询**：`/api/catalog?q=` 的匹配面从「仅名称包含」扩到**名称 / 别名 / 板块 / 区 / 城市**，并支持空格分词（每段都要命中）。

## 完成条件（每条都要能复跑）

### 后端模糊查询

- [ ] `q` 命中名称：`/api/catalog?q=望京` 返回名称含「望京」的小区（现有行为不回归）。
- [ ] `q` 命中别名 / 板块 / 区 / 城市：给定库里有 `alias`/`plate` 的数据，`q` 取这些字段的片段也能命中。
- [ ] 空格分词：`q=朝阳 望京` 两段都需命中（AND），结果集是单段结果的子集。
- [ ] 通配符按字面处理：`q=%`、`q=_` 不返回全量、不报 500。
- [ ] 大小写不敏感：拉丁字母片段小写可命中大写名称（现有用例继续过）。
- [ ] 空 `q` / 全空白 `q`：不参与过滤，等同不限。
- [ ] `total` 与分页切片一致；参数绑定顺序正确（不得出现 `total>0` 但 `items=[]`）。
- [ ] 补充单测到 `backend/tests/test_catalog.py`，覆盖以上各条。

### 前端 F-01

- [ ] 首页 hero 有搜索框，占位文案「搜索小区名称或地址…」，样式沿用既有变量（胶囊、`--gold`、`--line-strong`），不新增外链。
- [ ] 有词回车/点搜索 → `#/catalog?q=<编码后的词>`，结果列表展示。
- [ ] 空词点搜索 → `#/catalog`（不带 `q`），不报错。
- [ ] 结果页顶部保留「搜索：XX」并可清空（复用 `.poi-query-hint` 视觉或等价）。

- [ ] 浏览器返回首页时搜索框回填上次关键词。

### 前端 F-02

- [ ] 不引入路由库、不加第三方依赖。

## 实现提示（不强制）

- 模糊查询：`catalog.py` 里把 `_build_where` 的 `q` 分支抽成独立函数，关键词按空白 `split()`，每段生成
  `(lower(COALESCE(x.name,'')) LIKE ? OR ... alias / plate / district / city)`，段间 AND；
  用 `ESCAPE '\'` 转义 `%` `_` `\`。
- 返回：`history.length > 1` + `history.back()`；无来路 `location.replace('#/catalog')` 兜底。
  注意 `replace` 到同文档 hash 可能不触发 `hashchange`，需要兜底重绘。
- 有来路时按钮文案取「上一页标题」，可在路由层维护一份轻量栈（只存 hash），不依赖 `document.referrer`。
