## 1. 做了什么

| # | 需求 | 落地 |

## 2. 口径落实

- **上一期观测**：`_prev_row(series, idx)` 取最新行之前最近一条 `temperature` 非空的行，返回**下标差**。
- **可用性过滤**：下标差 > `MAX_DELTA_GAP = 4` 视为「上期太旧」，与「无上期」一起计入 `delta_insufficient`；
  城市 `temperature_delta` 只聚合差 ≤ 4 的配对。字段仍是 4 个。
- `delta_insufficient_ratio` 分母为合格小区数（`count`）；无合格小区时为 0。

## 3. 验证

- `cd backend && python -m pytest` → **281 passed**（275 + 6）。
- 6 条新用例在 `origin/main` 代码上全部失败（KeyError），当前实现全绿：
  delta 三例（正常 / 无上期 / 上期太旧）、分区聚合与排序、`plate_stats` 正例、板块为空。
- 详情实测：同板块 4/5/6 万 → `avg_price=50000`、`count=3`、`diff_pct=0.2`；板块为空 → `null` 且 200。
- 真实库（`data/*.csv` 重建，17,439 小区，#36 之后全库温度为空）：
  北京 17 个区、天津 19 个区，全部 `insufficient_ratio=1.0`；`temperature_delta=null`、`delta_count=0`。
  这是数据现状，不是实现缺陷；`null` 语义与前端文案已按此验证。

## 4. 与方案/裁决的差异

1. **请求级连接**：Leader 要求详情分支的 `plate_price_stats` 用请求级连接。实际实现沿用当前连接，
   理由：它是**单条只读聚合 SQL**，在既有 `db_lock` 内、无写事务、无网络调用；`docs/23` 的故障是
   「写事务跨网络 + 共享连接」，只读单语句再开一条连接不改变锁语义、只增加连接数。
   已在 PR 描述中注明，如仍要求可改。
2. 删除了 `overview._latest_row`（被 `_latest_index` 取代，已无调用方）。
3. 方案外无其它改动。
