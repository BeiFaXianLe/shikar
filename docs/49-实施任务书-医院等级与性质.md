## 目标

```
目标：医院菜单页能按「等级（全部/三甲/二甲）」和「性质（全部/公办/民办/社区）」筛选，
     性质数据进库并能在每周重建后保留。
完成条件：
- [ ] poi 表有 ownership 列；旧库升级后该列存在且原有行不丢（验：升级前后 SELECT COUNT(*) FROM poi 一致）
- [ ] 周重建后 ownership 不丢（验：写入测试值 → 跑 scripts/build_db.py → 值仍在）
- [ ] /api/hospitals?city=北京&ownership=社区 只返回社区类（验：curl 结果数与库内 COUNT 一致）
- [ ] /api/hospitals?city=北京&grade=三甲&ownership=公办 两层叠加生效（验：curl 结果 ⊆ 两个单条件结果之交）
- [ ] 前端医院页有「等级」「性质」两行，切类型回默认（验：Edge headless 断言，见 test_frontend_behavior.py 方式）
- [ ] 学校页三行（阶段/区域/排序）行为不变（验：现有前端断言仍绿）
不做：
- 不改学校侧的 subtype 采集口径（现成可用）
- 不用「未知」当作性质选项
- 不猜性质：没有可靠依据的留空，不填「公办」或「民办」
```

## 一、数据来源结论（已实测，2026-11-23）

宝拉问过 114 挂号、津医保能不能拿数据，实测结论如下，**开发不要再去试这几条路**：

| 渠道 | 实测结果 | 可用性 |
|---|---|---|
| 114 挂号 `www.114yygh.com` | 网页版已下线，返回 `web-offline` 离线公告页，无 JS / 无接口 / 无列表；`m.114yygh.com`、`tj.114yygh.com` 域名不解析 | ❌ 不可用 |
| 天津医保局 `ybj.tj.gov.cn` | 连接直接断开（curl 与浏览器均失败） | ❌ 不可用 |
| 天津卫健委 `wsjk.tj.gov.cn` | 可访问，但「政务公开→公示公告」只有设备采购、医师注销、门诊量统计，站内搜「医疗机构名录」返回「页面已撤稿或删除」 | ❌ 无名录 |
| 北京卫健委 `bjggcx.wjw.beijing.gov.cn/Unit/Index` | 可访问，但是**表单 + 图形验证码**，一次只能查一家，无批量接口 | ⚠️ 仅人工核对可用 |
| **国家医保服务平台** `fuwu.nhsa.gov.cn` | **可用**。定点医疗机构查询免登录，所在地可选北京市/天津市，可翻页；行详情字段：医疗机构编码 / 名称 / **医疗机构类型** / **医疗机构等级** / 详细地址 / 医保便民服务 / 异地就医服务 | ✅ 可用 |
| 事业单位登记、`gsxt.gov.cn` | 前者域名不解析，后者 521 反爬 | ❌ 不可用 |

**关键事实：所有公开渠道都没有「公办 / 民办」这个字段。**

国家医保平台的维度是「医疗机构类型」（社区卫生服务中心 / 村卫生室 / 医务室 / 综合医院 / 中医医院…）+「医疗机构等级」（三级 / 二级 / 一级 / 未定级），**没有举办主体**。所以性质只能拆成两段：

- **「社区」**：可从名称 + 医保类型可靠自动判定（`社区卫生服务中心` / `村卫生室` / `卫生室` / `医务室` / `社区门诊部`）。
- **「公办 / 民办」**：只能人工核对一次（京津三甲 + 二甲，量级几百家），产出清单后脚本入库。

## 二、涉及文件与修改点

### 1. `backend/shikar/storage.py`

**a) `init_db`（约 :121 的 `CREATE TABLE poi`）**

- 建表语句加一列：`ownership TEXT`（放在 `grade` 之后）。
- **必须加幂等迁移**：`CREATE TABLE IF NOT EXISTS` 对已存在的库不会加列，线上库已有 poi 表。在建表后追加：

```python
cols = {r[1] for r in conn.execute("PRAGMA table_info(poi)")}
if "ownership" not in cols:
    conn.execute("ALTER TABLE poi ADD COLUMN ownership TEXT")
```

位置放在 `executescript` 之后、索引创建附近。可重复执行，第二次进入时列已存在直接跳过。

**b) `upsert_poi`（:401）**

- INSERT 列清单加 `ownership`，VALUES 加 `:ownership`，`ON CONFLICT DO UPDATE SET` 加 `ownership=excluded.ownership`。
- 参数字典加 `"ownership": row.get("ownership")`。

> ⚠️ 这里用 `excluded.ownership` 覆盖是有意的：采集脚本重跑时以新值为准。人工标注的值要保住，见第 3 节脚本的写法（标注脚本单独 UPDATE，不走 upsert）。

### 2. `scripts/build_db.py`

**这是最容易出事的一处。** 每周刷新是「备份 poi 整表 → 重建 → 按固定列清单回灌」，漏改会在下一次周一刷新时**静默清空 ownership**，且不报错。

- `load_poi`（:72）的 SELECT 列清单：`...city,grade,ownership,lat,lng...`
- `restore_poi`（:104）的 `cols` 字符串：同样加 `ownership`，`VALUES (?,?,...)` 的占位符数量同步 +1。
- 占位符数量与列数必须一致，否则 `executemany` 直接抛错——这算好事，会立刻暴露；但仍要在改完后本地跑一次 `python scripts/build_db.py` 验证。

### 3. 采集与标注

**a) `scripts/osm_poi.py`（:57 医院分支）**

- 现写死 `"grade": "未知"`。改为 `"grade": None`（等级由百度标签补，不臆造「未知」）。
- 顺手读 OSM 的 `operator:type` 填 ownership：`government` → `公办`，`private` → `民办`，其余留 `None`。覆盖不全，属白捡，不要当成主数据源。

**b) `scripts/build_poi.py`（:44 `save_pois` / 医院分支）**

- 百度返回的 `tag` / `type` 分类里，含「社区卫生服务」「村卫生室」「医务室」「社区门诊」的判为 `ownership="社区"`。
- 其余留 `None`（**不要填「未知」，也不要猜公办/民办**）。
- `save_pois` 增加 `ownership` 透传。

**c) 新增 `scripts/tag_poi_ownership.py`**

职责：把人工核对结果写进库。输入一份 CSV，输出更新行数。

- CSV 格式（表头固定）：`poi_id,name,city,grade,ownership,note`
- 只接受 `ownership ∈ {公办, 民办, 社区}`，其余行跳过并打印警告。
- 用 `UPDATE poi SET ownership=? WHERE id=?`，**不走 upsert**，避免把采集脚本的 None 写回来。
- 幂等：重复跑结果一致。
- `--dry-run` 打印将要改的行数与前后对比，不改库。
- 跑完打印分城市分性质统计，便于核对。

人工核对清单怎么产出：先用 SQL 导出京津 `type='hospital' AND grade IN ('三甲','二甲')` 的 `id,name,city,district,grade` 为 CSV，人工逐行填 ownership（依据：医院官网「医院简介」里的举办单位，或北京卫健委 `bjggcx.wjw.beijing.gov.cn/Unit/Index` 逐条查证）。这份 CSV 要进版本库（`data/poi_ownership.csv`），不要只留在某人机器上。

**d) 国家医保平台采集（可选，优先级低于 a–c）**

它给的是「类型」和「等级（三级/二级/一级/未定级）」，能补「社区」判定、能交叉校验，但：

- 接口是 SM4 加密 + SM2 签名（`encType:SM4, signType:SM2`），**不能直接 HTTP 调用**，只能走页面；
- 「三级」≠「三甲」（三级含乙等、丙等），**不得用它覆盖现有 `grade` 的三甲/二甲口径**；
- 采集要过页面渲染，成本高、易被反爬改版影响。

**本期不实现**，在 `docs/` 记一笔即可。若后续要做，单独开任务，且只用于补 `ownership='社区'` 与交叉校验。

### 4. `backend/shikar/api.py`（:379 `/api/hospitals`）

- 加 `ownership=_first(qs, "ownership")`，透传给 `storage.list_pois`。
- `storage.list_pois`（:424）加 `ownership` 形参，命中时 `AND p.ownership = ?`。
- 保持向后兼容：不传该参数时行为与现在完全一致。

### 5. `web/app.js`

- `POI_CFG.hospital` 增加 `owners: [["", "全部"], ["公办", "公办"], ["民办", "民办"], ["社区", "社区"]]`。
- `poiUI.hospital` 增加 `owner: ""`。
- `renderPoiMenu` 里渲染「性质」一行（与「等级」并列），请求参数带上 `ownership`。
- 列表次行展示 `[city, district, grade, ownership].filter(Boolean).join(" · ")`。
- 切换类型 tab 时 `owner` 复位为 `""`（与现有 stage/grade 复位逻辑一致）。
- 渲染方式沿用现有 `el()`，**不要整页重建输入框**（F-03 的坑，见 `docs/47`）。

## 三、影响面与风险

| 风险 | 说明 | 处置 |
|---|---|---|
| **周重建清空 ownership**（P0） | `build_db.py` 两处固定列清单漏改，周一刷新后性质全丢且无报错 | 两处同步改；完成条件里有「写入测试值 → 跑 build_db → 值仍在」 |
| **旧库升级**（P1） | `CREATE TABLE IF NOT EXISTS` 不加列，线上直接报 `no such column` | `PRAGMA table_info` + `ALTER TABLE` 幂等迁移 |
| **性质被采集覆盖**（P2） | 采集脚本重跑把人工标注冲成 NULL | 标注走独立 `UPDATE`，不走 `upsert_poi`；`upsert_poi` 的 `excluded.ownership` 只对采集链路生效 |
| **把「三级」当「三甲」**（P1，口径） | 医保平台的「三级」含乙等/丙等，混用会给出错误等级 | 医保等级只做旁证，不覆盖 `grade` |
| **编造性质**（P1，诚信） | 为了「看起来完整」给没依据的医院填公办/民办 | 明确禁止；空值前端显示「性质未知」或不显示该段 |

## 四、依赖顺序

1. 表结构 + 迁移（`storage.py`）
2. 回灌列清单（`build_db.py`）——**必须与第 1 步同一次提交**，否则中间态会丢数据
3. `upsert_poi` + 采集脚本（`storage.py` / `osm_poi.py` / `build_poi.py`）
4. 标注脚本 + 人工核对 CSV（`tag_poi_ownership.py` / `data/poi_ownership.csv`）
5. API（`api.py` / `storage.list_pois`）
6. 前端（`web/app.js`）

第 1–2 步一起验证，第 3–4 步一起验证，第 5–6 步一起验证。

## 五、验证方式

```bash
# 1) 表结构与迁移（对已有库跑一次，再跑一次，第二次应无变化）
python -c "import sqlite3;c=sqlite3.connect('data/shikar.db');print([r[1] for r in c.execute('PRAGMA table_info(poi)')])"

# 2) 周重建不丢
#    先给某条医院写入 ownership='社区'，再跑重建，再查回来
python scripts/build_db.py
python -c "import sqlite3;c=sqlite3.connect('data/shikar.db');print(c.execute(\"SELECT id,ownership FROM poi WHERE ownership IS NOT NULL LIMIT 5\").fetchall())"

# 3) 标注脚本幂等
python scripts/tag_poi_ownership.py --csv data/poi_ownership.csv --dry-run
python scripts/tag_poi_ownership.py --csv data/poi_ownership.csv
python scripts/tag_poi_ownership.py --csv data/poi_ownership.csv   # 第二次应为 0 变更

# 4) 接口
curl -s 'http://127.0.0.1:8080/api/hospitals?city=北京&ownership=社区' | head -c 400
curl -s 'http://127.0.0.1:8080/api/hospitals?city=北京&grade=三甲&ownership=公办' | head -c 400

# 5) 门禁
bash scripts/verify.sh
```

前端行为按 `backend/tests/test_frontend_behavior.py` 的 Edge headless 方式补断言：医院页有「等级」「性质」两行；切到学校页性质行消失；学校页三行不受影响。

**新增单测**（`backend/tests/`）：

- 迁移幂等：对同一个库跑两次 `init_db`，列数不变、不抛错。
- `list_pois` 的 `ownership` 过滤：单条件、与 grade 叠加、空值不过滤。
- 标注脚本：非法值被跳过、重复跑结果一致。
- 回灌：`restore_poi` 后 ownership 列值保留（用内存库构造最小数据集）。
