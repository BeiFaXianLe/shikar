## 4. 每文件修改点

### 4.1 `backend/shikar/catalog.py` — `query_catalog`

1. 函数签名新增 `center: Optional[tuple[float, float]] = None`（顺序：`lng, lat`，与项目其它坐标口径一致）。
2. `sort` 白名单（现 `catalog.py:153`）增加 `"distance_center"`；传入该值但 `center is None` 时抛 `ValueError("距离排序需要 center")`。
3. 当 `sort == "distance_center"`：
   - `where_sql += " AND x.lng IS NOT NULL AND x.lat IS NOT NULL"` —— 无坐标小区不参与、也不占 LIMIT 名额；
   - `order = "((x.lng - ?)*(x.lng - ?)*? + (x.lat - ?)*(x.lat - ?)) ASC, " + stable`，
     `order_params = [mid_lng, mid_lng, cos2, mid_lat, mid_lat]`，其中 `cos2 = math.cos(math.radians(mid_lat)) ** 2`；
   - 用平方等距近似做**排序键**（纯四则运算，不依赖 SQLite 数学函数扩展）；城市尺度下与真实球面距离同序。
4. SELECT 仅在 `center is not None` 时追加 `x.lng AS lng, x.lat AS lat`；其它调用方响应字段保持逐字节不变。
5. 参数绑定顺序改为：
   `distance_params + metric_join_params + params + order_params + [size_n, offset]`
   （SQL 文本占位符顺序：SELECT 内 `distance_sql` → FROM 内期次 → WHERE → ORDER BY → LIMIT/OFFSET，必须逐段对应）。
6. 约束说明：`_clamp_page_size` 上限为 `_MAX_PAGE_SIZE = 200`，与 `_COMMUTE_MAX_DRIVING = 200` 相等，本方案依赖这一相等关系；将来若调大候选数，必须同时放开 clamp，否则会退化为「截断后再排序」。

### 4.2 `backend/shikar/catalog.py` — `select_commute_candidates`

改为两次查询，删除现有那次 `SELECT id,lng,lat FROM xiaoqu WHERE id IN (...)`：

1. `base = query_catalog(..., page=1, page_size=1, <原有过滤条件>)` → `total_matched = base["total"]`；为 0 时直接返回空结构。
2. `near = query_catalog(..., page=1, page_size=min(max_candidates or 200, 200), sort="distance_center", center=(mid_lng, mid_lat), <同一批过滤条件>)`：
   - `with_coords = near["total"]`（COUNT 与分页共用同一 WHERE，含坐标条件）；
   - `items = near["items"]`，此时已带 `lng/lat`。
3. 对 `items`（≤200 条）用 `_haversine_km` 按真实距离再排一次，保持既有输出顺序语义。
4. `truncated = with_coords > len(items)`。
5. 返回结构不变：`{"items", "total_matched", "with_coords", "truncated"}`。

### 4.3 `backend/shikar/commute.py` — transit 分支

1. 新增 `_classify_upstream(exc) -> str`：`TimeoutError`、或 `URLError.reason` 含 `timed out` → `"timeout"`；其余 → `"upstream"`。
2. 循环内保留逐条 `try/except`，但统计扩展为 `stats["attempted"]`、`stats["failed"]`；记录最后一次异常用于错误消息。
3. **短路**：连续 3 条失败且 `stats["computed"] == 0` → 立即 `raise CommuteError(kind, f"公交上游连续失败：{exc}", partial=stats)`，不再烧完剩余 OD 配额。
4. **收尾**：循环结束若 `stats["computed"] == 0 and stats["attempted"] > 0` → 抛同类错误（覆盖候选不足 3 条的情况）。
5. 部分失败：`stats["partial"] = stats["failed"] > 0`，其余照旧返回 200。
6. 驾车分支不动（其上游错误已由 `_get_json` 分类）。

### 4.4 `backend/shikar/api.py`

1. `_handle_commute` 的响应 `base` 增加 `"partial": bool(stats.get("failed"))`（附加字段，不删改既有键）。
2. 错误分支不变：`_COMMUTE_ERROR_STATUS` 已把 `upstream→502`、`timeout→504` 映射好。
