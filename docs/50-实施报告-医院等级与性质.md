## 关键实现说明

### 1. 迁移与回灌必须同一次提交

`CREATE TABLE IF NOT EXISTS` 对线上已有 `poi` 表不会加列。`init_db` 在建表脚本执行后补：

```python
poi_cols = {r[1] for r in conn.execute("PRAGMA table_info(poi)")}
if "ownership" not in poi_cols:
    conn.execute("ALTER TABLE poi ADD COLUMN ownership TEXT")
```

`build_db.py` 的两处固定列清单（`load_poi` / `restore_poi`）与迁移在同一提交内改完。
旧库（还没有 ownership 列）备份时用 `NULL AS ownership` 占位，回灌仍是 13 列，不会因列数不等让周一刷新炸掉或被静默清空。

### 2. 人工标注不被采集覆盖

- upsert 仍按任务书用 `excluded.ownership`（采集以新值为准）；
- `tag_poi_ownership.py` 只做 `UPDATE`，不 upsert，避免把采集的 NULL 写回；
- `osm_poi.py` 重导会 DELETE 当前城市旧 OSM 行，因此先按 id 记下人工 `ownership`，重建时恢复；
- `build_poi.py` 重跑时若本次判不出性质（None），沿用库里已有值。

### 3. 数据口径

- 等级仍只认 `三甲 / 二甲`；国家医保平台的「三级」含乙等/丙等，**不覆盖 `grade`**；
- 「社区」可由百度分类自动判定；**「公办 / 民办」公开渠道没有该字段**，只能人工核对后写 CSV；
- 没有依据的行留空，前端不显示该段，不填「未知」。

## 数据覆盖率（如实说明）

- `data/poi_ownership.csv` 目前**只有表头，0 家人工核对**；
- 本次没有联网跑采集，也没有给任何医院编造性质；
- 线上现有 `ownership` 预期为 NULL，直到：
  1. 下一次跑 `build_poi.py`，「社区」由分类自动落库；
  2. 人工按 CSV 核对京津三甲/二甲后跑 `tag_poi_ownership.py`，公办/民办才有值。
- PR 合并不要求 CSV 有数据；但「性质」筛选在核对完成前，公办/民办会是空结果。
