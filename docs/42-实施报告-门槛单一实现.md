## 1. 核查结论（与报告前提不一致，必须先说清）

**main 上 `pipeline.recompute` 自 #36（`852ac47`）起已经带门槛**：

- `backend/shikar/pipeline.py` 有 `MIN_PERIODS/MIN_SPAN_DAYS/MAX_GAP_DAYS` 与 `is_sufficient()`；
- `recompute` 先判 `sufficient`，不满足写 `temperature=None, stage=None`；
- 本地复现：2 期序列（2019-02 + 2026-W46）经 `ingest` → `recompute` 后两行 temperature 均为 `None`；
- 编号核对：`git ls-tree origin/main backend/shikar/pipeline.py` 与 `show` 均可见 `is_sufficient`（40-90 行）。

所以线上「全员温度=50」不可能由 main 的 recompute 产生。最可能是 **`/opt/shikar` 的运行副本不是 main**（未 pull 到 #36 之后，或被旧副本/安装包 shadow）。建议在服务器上先核对：

```bash
git -C /opt/shikar log -1 --oneline
grep -n "is_sufficient" /opt/shikar/backend/shikar/pipeline.py
python3 -c "import sys; sys.path.insert(0,'/opt/shikar/backend'); from shikar import pipeline; print(pipeline.__file__, hasattr(pipeline,'is_sufficient'))"
```

若第二条 grep 无输出，就是部署副本陈旧，更新后重跑 `recompute_metrics.py` 即可；不需要改代码。

## 2. 真正需要修的：门槛有两份实现

- `scripts/build_db.py` 自带 `parse_week()` + `sufficient()`（约 222-247 行）；
- `backend/shikar/pipeline.py` 另有一份 `is_sufficient()`。

两份各算各的，正是这次「改了一条漏另一条」的结构性原因。本 PR 做去重：

- 删除 build_db 的本地 `parse_week`/`sufficient`；
- 改为 `pipeline.is_sufficient(weeks_by.get(xid, set()))`；
- 阈值仍只定义在 `pipeline`（MIN_PERIODS=3 / MIN_SPAN_DAYS=365 / MAX_GAP_DAYS=365），数值未改。

## 3. 测试（+4，全量 306 passed）

| 用例 | 断言 |
|---|---|
| `test_recompute_after_ingest_history_keeps_null` | 模拟 ingest_history（直接 upsert 2 期、temperature=None）→ recompute 两次仍为 NULL（锁住线上事故形态） |
| `test_recompute_idempotent_for_sufficient_series` | 5 期、跨度 480 天 → 非 NULL，两次 recompute 结果一致 |
| `test_build_db_uses_pipeline_gate` | `build_db.pipeline.is_sufficient is pipeline.is_sufficient`；源码不得再出现本地 `parse_week`/`sufficient` |
| `test_build_db_and_recompute_agree_on_same_data` | 同一份数据（1 合格 + 1 不足）先 build_db 建库、再 recompute 重算，两次「是否有温度」判定必须一致 |

有效性说明（如实）：`test_build_db_uses_pipeline_gate` 在 main 的 build_db 上失败（AttributeError，无 pipeline 引用），符合「先红」；两条 recompute 回归在 main 的 pipeline 上本来就能过——因为 main 的门槛是对的，它们的作用是锁住生产路径。
交叉对照那条已用变异验证：把 build_db 的调用改成 `min_periods=1` 后，build_db 写出 2 行温度、recompute 判全 NULL，断言立刻失败——门槛一旦分叉就会被这条抓住。
