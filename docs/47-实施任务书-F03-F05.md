## F-03 · 所有搜索框输入时丢焦点（P0，阻断录入）

### 根因（已线上复现）

`web/app.js:1922 renderPoiMenu` 的搜索框：

```js
function applySearch() {
  var v = searchInput.value.trim();
  if (v === (ui.q || "")) return;
  ui.q = v;
  renderPoiMenu(type);        // ← 整页重建
}
searchInput.addEventListener("input", function () {
  debounceTimer = setTimeout(applySearch, 300);   // ← 300ms 后必重建
});
```

`renderPoiMenu` 第一行就是 `appEl.innerHTML = ""`，输入框节点被销毁重建，浏览器焦点回到 `body`。
用户刚打一个字，300ms 后页面重建，光标消失，无法继续录入。

**线上复现证据**（Edge headless，`#/schools` 输入「中关」）：

```
after typing 中关: {"value":"中关","focused":false,"active":"BODY"}
```

### 影响范围

同一模式出现在三处，都要改：

| 位置 | 场景 |
|---|---|
| `web/app.js:1922 renderPoiMenu` | 学校 / 医院 / 高铁站 三个菜单页共用 |
| `web/app.js:407 renderOverview` hero 搜索（PR#47 新增） | 首页搜索框，回车才提交，不触发重建，风险较低但需确认 |
| `web/app.js:1248 render()`（筛选抽屉） | 已有焦点恢复逻辑（`savedFocusId` + `selectionStart`），可作为参考实现 |

### 修法（原型已验证）

**搜索框与筛选条只创建一次；输入变化只刷新结果列表与提示行，不碰输入框节点。**

```js
// 建一次
var listHost = el("div", { class: "poi-list" });
var hintHost = el("div");

function paintResults() {
  hintHost.innerHTML = "";
  listHost.innerHTML = "";
  // ...只填充这两块
}

searchInput.addEventListener("input", function () {
  clearTimeout(debounceTimer);
  debounceTimer = setTimeout(function () {
    ui.q = searchInput.value.trim();
    paintResults();          // ← 不调用 renderPoiMenu
  }, 300);
});
```

城市 / 阶段 / 等级切换仍可整页重绘（那些是点击，不是连续输入）。

### 完成条件

- [ ] 在学校 / 医院 / 高铁站任一页，连续输入 5 个以上字符，焦点全程不丢（`document.activeElement` 始终是输入框）。
- [ ] 输入过程中光标位置保持在末尾，不回跳。
- [ ] 结果列表随输入实时收敛（防抖 300ms 保留）。
- [ ] 点「清空」后焦点回到输入框。
- [ ] 切换城市 / 阶段 / 等级后结果正确，输入框保留已输入关键词。
- [ ] 补一条可执行断言到 `backend/tests/test_frontend_behavior.py`（沿用现有 Edge headless + CDP 方式）：输入后断言 `document.activeElement` 仍是输入框。
- [ ] 证据：改前复现（焦点丢失）+ 改后同步骤（焦点保持）各一段输出。

### 不做

- 不改防抖时长（300ms 是既有行为）。
- 不加搜索联想 / 下拉补全。

## F-04 · 学校 / 医院 / 高铁站不支持按区域查找（P1）

### 根因（线上实测）

三个问题叠在一起：

**① 数据缺失** — POI 表 `district` 大面积为空：

| 类别（北京） | 总数 | district 为空 | 覆盖率 |
|---|---|---|---|
| 学校 | 1949 | 1887 | 3.2% |
| 医院 | 450 | 431 | 4.2% |
| 高铁站 | 25 | 0 | 100% |

（天津：学校 1060 条 / 19 条有区；医院 253 条 / 3 条有区）

**② 格式不统一** — 有值的也不统一：`朝阳` / `朝阳区` / `Chaoyang 朝阳区` / `望京地区` / `市辖区` 混用。
`storage.list_pois`（`backend/shikar/storage.py:439`）用的是 `p.district LIKE ? + '%'`，
所以前端传「朝阳」能匹配「朝阳区」，但传「朝阳区」匹配不到「朝阳」。

**③ 前端没有控件** — `renderPoiMenu` 只有城市下拉，没有区筛选。

### 可用的回填路径（已验证）

用「最近小区的 district」回填 POI 的区。抽样 20 条无区学校，14 条能通过
`/api/poi/{id}/communities?limit=1` 拿到有区的小区（70%）。

### 修法（原型已验证交互）

1. **数据侧**：新增回填脚本（建议 `scripts/backfill_poi_district.py`），
   对 `district IS NULL` 的 POI，取最近 3 个小区的 district 众数回填；
   只填空值，不覆盖已有值。可复跑、幂等。
2. **口径统一**：读时归一化——去掉「区 / 县」后缀、剥离英文前缀
   （`Chaoyang 朝阳区` → `朝阳`），与 `xiaoqu.district` 同一套区名。
   建议放在 `storage.list_pois` 的 district 过滤里，用归一化后的值比较。
3. **前端**：菜单页加一行「区域」筛选（胶囊组，参考原型 `f04`），
   区列表来自 `/api/districts?city=`（与「找小区」同源），不硬编码。
4. **诚实呈现**：仍然没有区的条目显示「区未知」，不猜、不隐藏。

### 筛选层级（原型已含，四层叠加）

按宝拉 16:12 / 16:23 两次补充要求，菜单页要有完整筛选层级，**不能只剩区域一层**：

| 层级 | 学校 | 医院 | 高铁站 |
|---|---|---|---|
| 类型 tab | 学校 / 医院 / 高铁站 | 同左 | 同左 |
| 阶段 / 等级 / 性质 | 小学 / 初中 / 高中（默认小学） | 「等级」全部 / 三甲 / 二甲；「性质」全部 / 公办 / 民办 / 社区 | — |
| 区域 | 按区胶囊，随上层筛选重算 | 同左 | 同左 |
| 排序 | 学校排名 / 周边小区最多 / 名称 | 周边小区最多 / 名称 | 周边小区最多 / 名称 |

**医院「性质」是新增维度，数据库里没有**：`poi` 表只有 `grade`（三甲 / 二甲），
没有公办 / 民办 / 社区这一列。原型用假数据演示。实施时二选一，并在 PR 里写明选了哪个：

- **方案 A（推荐）**：先只做「等级」筛选（数据现成），「性质」留空位并显示「待数据侧采集」；
- **方案 B**：改 `poi` 表加 `ownership` 列 + 采集/标注脚本，工作量更大，需单独确认。

不要用猜测值填充性质，也不要把「未知」当成一个性质选项。

### 学校排名（原型已含）

- 排序项「学校排名」，默认选中。
- 名次徽章 `#1 #2 …` 显示在列表行左侧。
- 排序行下方有一行规则小字，**必须写明公式**，不能让用户以为这是教委官方排名。
- 原型用的规则：`综合热度 = 周边小区数 × 等级系数（重点校 1.5，普通校 1.0）`，降序，同分按名称。
- **名次只在当前筛选结果内计算**（同一阶段、已选区域），不跨阶段混排。
- 规则小字必须包含这句限定：「仅反映本站已收录小区的覆盖情况，不是教委官方排名」。

### 完成条件

- [ ] 回填脚本可复跑、幂等；跑完统计 `district` 覆盖率（改前 / 改后各一组数字）。
- [ ] `/api/schools?city=北京&district=海淀` 只返回海淀的学校，结果数 > 0。
- [ ] `/api/hospitals?city=北京&district=朝阳`、`/api/hsr?city=北京&district=丰台` 同样可用。
- [ ] 区名归一化：传 `朝阳` 与传 `朝阳区` 结果一致。
- [ ] 前端三个菜单页都有区域筛选；选中后结果收敛，切城市时区列表跟着换。
- [ ] 学校阶段筛选（小学 / 初中 / 高中）保留且生效；切阶段后区域胶囊按新结果重算。
- [ ] 医院「等级」筛选（全部 / 三甲 / 二甲）生效；「未知」不作为选项出现。
- [ ] 医院「性质」按选定的方案 A 或 B 落地，PR 里写明；不出现编造的性质值。
- [ ] 学校「学校排名」排序生效：名次徽章按当前筛选结果从 #1 连续编号，规则小字含「不是教委官方排名」。
- [ ] 四层筛选叠加正确：类型 → 阶段/等级 → 区域 → 排序，任意组合结果自洽。
- [ ] 无区条目显示「区未知」，不被筛选项错误吞掉（选「全部」时仍可见）。

### 不做

- 不自行给医院填「性质」——数据没有就是没有，按方案 A 显示「待采集」。

## F-05 · 数据里的英文 / 纯数字名称（说明性，主要是口径）

### 结论

**不是程序生成的，是抓取源页面的原始名称。**

线上库 17439 个小区全量分类：

| 类别 | 数量 | 占比 | 判断 |
|---|---|---|---|
| 纯中文 | 14881 | 85.3% | 正常 |
| 中英 / 含数字 | 2555 | 14.7% | **多数是真实案名** |
| 纯英文 / 纯数字 | 3 | 0.02% | 源数据残缺 |

按来源拆：

| 来源 | 条数 | 中英/含数字 | 纯英文 |
|---|---|---|---|
| 链家 2019 全量快照（公开数据集） | 16624 | 2519 | 3 |
| 房天下 2026 当期快照 | 3830 | 77 | 0 |

典型样例：

- `珠江帝景B区` / `富力城D区` — 楼盘分区标准写法，**真名**
- `唐宁ONE` / `UHN国际村` / `硅谷SOHO` — 真实案名
- `合生霄云路8号` — 门牌号是案名一部分
- `西坝河北里25号院` / `11站` — 老小区无正式案名，链家按地址登记
- `CLASS` / `LOFTEL` / `Wehouse` — **链家原库就残缺**，只剩英文后缀

### 处理口径（本期只做口径确认 + 标注，不做清洗）

- **中英混合 / 含数字**：保留。模糊查询已能按中文片段、英文片段、数字分别命中。
- **地址式名称**：保留，列表里加「地址」标记，让用户知道这不是案名。
- **纯英文残缺（3 条）**：保留原样并标注「源数据名称不全」，**不猜、不拼凑**；如要从源站补全，另开任务。
- **拼音搜索**：仍按 `docs/16-Feature-Map.md` F4 裁定，属后续里程碑，本期不做。

### 完成条件

- [ ] 数据侧：在 `docs/` 或 `data/README.md` 记录这份分类口径（可复用原型里的统计）。
- [ ] 前端（可选，低优先）：地址式名称加「地址」标记。
- [ ] **不改任何小区名称数据**。
