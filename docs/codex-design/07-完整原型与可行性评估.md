## D 双点通勤的效果与口径

![双点加权通勤原型](../evidence/full-prototype/commute-balanced.jpg)

| 模式 | 计算口径 | 产品意义 |
|---|---|---|
| A 优先 | `0.8 × tA + 0.2 × tB` | 更多照顾 A 的通勤 |
| 均衡 50/50 | `0.5 × tA + 0.5 × tB` | 降低双方平均时间 |
| B 优先 | `0.2 × tA + 0.8 × tB` | 更多照顾 B 的通勤 |
| 最慢一方优先 | `max(tA, tB)` | 降低通勤最慢一方的时间，权重不参与 |

原型样例：50/50 第一名为“四季雅苑”，A 80% 第一名为“知春雅苑”。
“最慢一方优先”样例第一名为“四季雅苑”，分数 20 分钟。
这些结果仅证明交互和排序可表达需求。
真实通勤需要地点坐标、出发时段、交通方式与路线策略。

建议默认 50/50 加权均值，并保留第二种均衡策略。
若要求两边都不超过某个时间，应另设 A/B 时间上限。

## E 数据模型与技术选型

```flow LR
小区与地铁及设施数据 -> 坐标规范化
坐标规范化 -> 离线距离预计算
离线距离预计算 -> 地铁关系表
离线距离预计算 -> 设施关系表
离线距离预计算 -> 物化宽表
首页筛选 -> 物化宽表
首页筛选 -> 地铁关系表
首页筛选 -> 设施关系表
设施 Top20 -> 设施关系表
首页候选 -> 通勤路径计算
通勤路径计算 -> 路径缓存
路径缓存 -> 双点评分与排序
```

| 方案 | 查询能力 | 运维与成本 | 建议 |
|---|---|---|---|
| SQLite + 明细关系 + 物化宽表 | 预计算筛选、设施明细与 Top20 | 本地单文件；需维护离线重建 | 当前首选 |
| PostgreSQL + PostGIS | 任意半径空间查询、多城市与并发服务 | 增加数据库部署、迁移与运维 | 扩规模时评估 |
| 只做宽表 | 固定摘要筛选 | 初期简单；难以表达任意设施与排名 | 不作为唯一数据底座 |

| 数据表 | 职责与关键设计 |
|---|---|
| 现有 `xiaoqu` | 小区身份、城市、坐标；价格继续来自已有指标 |
| `poi` | 学校 / 医院 / 高铁；稳定 ID、城市、阶段或等级、坐标、来源、版本 |
| `community_poi` | 小区与设施距离；唯一键 `(community_id, poi_id)` |
| `community_subway` | 每小区每线路的距站与距线路距离；支持多线路筛选 |
| `community_features` | 每小区一行；固定半径计数、各阶段最短距离、三甲最短距离、更新时间 |
| `commute_cache` | 起终点、方向、方式、时段、路线策略、供应商、时间结果与过期时间 |

Top20 建索引 `(poi_id, distance, community_id)`，稳定升序后取 20 条。
线路筛选查关系表，不能只查全局最近线路。
指定学校或医院筛选查明细关系，不能只看宽表摘要。
宽表与关系表记录同一数据版本，并事务更新。
未知坐标或等级保留空值，不能解释为零距离。
离线计算按城市与空间网格预筛，避免所有小区与所有设施全量配对。

## F 真实数据与调用成本

| 能力 | 数据要求 | Key 与成本 | 需要解决的事实 |
|---|---|---|---|
| 地铁 | 线路走向、站点、小区坐标 | 公开离线文件可不使用商业 Key | 数据许可、版本、坐标系、覆盖范围 |
| 学校 | 阶段、校区位置、名单 | 商业 POI 搜索需 Key；可离线导入 | 校区去重；重点与对口须独立来源 |
| 医院 | 院区位置、等级 | 商业 POI 搜索需 Key；可离线导入 | 不能仅凭普通 POI 分类推断三甲 |
| 高铁 | 车站位置、高铁属性 | 商业 POI 搜索需 Key；可离线导入 | 火车站分类不保证有高铁服务 |
| 通勤 | 地址定位与驾车 / 公交路径服务 | 通常需 Key、权限与配额 | 批量能力、有效期与展示条款需核实 |

主仓库最新坐标恢复提交为 `eab0fb3`，提交说明为 16624 个带坐标小区。
当前恢复脚本未记录小区坐标系，正式距离导入需先明确。
WGS84、GCJ02、BD09 不可直接混算。
离线地铁数据的免费获取不代表其许可与覆盖已经验证。

通勤建议先筛选到最多 200 个候选，再计算到 A/B 的时间。
200 个候选需要最多 400 个 OD 结果，请求次数取决于 API 批量能力。

超出候选上限时提示缩小范围，不能静默把部分结果当成全量排名。
有效缓存命中后，改变权重仅需本地重新排序。
设置请求预算、超时与失败状态；缓存有效期遵守供应商条款。
当前未核实套餐价格，不承诺费用或免费额度。

## G 市场判断与可接受风险

“没有类似产品”目前不能成立为确定结论。
本轮核实了新加坡官方 [OneMap School Query](https://www.onemap.gov.sg/school)。
它提供学校阶段分类及住宅到小学距离查询。
页面说明住宅到学校距离服务按年度更新。
因此，学校距离查询本身已有相近能力。

你的差异化假设是京津小区行情与多种生活条件整合。
设施反向 Top20 与双点通勤权重，是值得验证的组合体验。
本轮没有全面核验中国房产平台、应用、小程序和海外产品。
尚不能判断是否存在提供全部组合能力的直接竞品。
建议使用真实小区样本，让目标用户比较两个工作地点的候选结果。

| 分类 | 结论 |
|---|---|
| 必须解决 | 坐标系、设施属性来源、价格时间口径、路径 API 配额与缓存条款 |
| 建议完善 | A/B 通勤上限、院区与校区区分、线路版本、数据刷新与覆盖报告 |
| 可接受的初期风险 | 直线距离只作为粗筛；部分小区缺坐标；历史价格需明确标注时间 |
