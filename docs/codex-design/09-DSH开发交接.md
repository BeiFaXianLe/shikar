## 完整功能范围

1. 地铁沿线查找小区：按城市、多条线路、指定站点、距离与口径筛选。站点附近和线路附近分别计算；多线取 OR，其余类别取 AND。
2. 记录小区周边医院、学校、高铁：学校区分小学、初中、高中；支持自定义阶段、等级、距离、指定设施筛选。设施独立菜单展示明细和周边小区 Top20，并一键带回首页组合查询。
3. 双点通勤：两个具体地点、驾车或公交/地铁、A/B 权重和均衡策略。展示 tA、tB 与加权时间。等权平均与最慢一方策略分开说明，调整权重复用已得到的路径结果。
4. 筛选界面：默认只展示城市、地铁、参考单价；其他条件在分组抽屉。chips 与查询一致，可逐个删除；结果主行名称和价，次行展示已启用条件的匹配摘要。手机筛选弹层，键盘、取消/应用、错误与空态均可操作。

## 技术方案与必须修正事项

沿用 Python 标准库 + SQLite + 原生 HTML/CSS/JS。无需 Java 重写、前端框架升级或 PostGIS 部署。

- `poi` + `community_poi` 存明细与距离；稳定外键连接已有 `xiaoqu.id`。
- `community_features` 物化固定口径摘要；明细、指定设施和 Top20 查关系表。
- `community_subway` 存每小区每线路关系；不能用全局最近线路代替选定线路距离。
- Top20 使用 `(poi_id, distance, community_id)` 索引，距离相同按 ID 稳定排序。不足 20 条如实显示；查询覆盖半径与 UI 上限一致。
- 医院等级与距离、学校阶段与距离须由同一设施满足，不能用互不相干的聚合字段拼出命中。
- 缺坐标、等级、价格和路径结果保留未知状态，不能记成 0；附近学校不写成对口学校。
- 价格每条带期次与来源；同期筛选/排序口径明确，2019 价格不作为无提示的当期行情。
- 通勤先粗筛；超过候选上限时要求缩小范围或明确选取范围。缓存键含方向、坐标、方式、供应商、出发时段和路线策略。
- 新增网络请求不能占用现有 API 的全局数据库锁；ETL 原子更新关系与宽表版本；不覆盖真实行情主表。
- 旧 `/api/overview`、`/api/xiaoqu*` 保持兼容。新增 `/api/subway/lines`、`/api/schools`、`/api/hospitals`、`/api/poi/{id}/communities`、`/api/commute`，扩展 `/api/catalog`。
